# Faction PvE and original contraband searches

`POST /services/open` targets an actual Core3 recruiter NPC. Recruiters also appear in the normal bounded `state.terminals` collection. The terminal uses `kind: recruiter`, original conversation text, current rank, original next promotion cost, and the source-ordered equipment/uniform/furniture reward list with original inventory previews. No installation, base, hireling or campaign purchasing is exposed.

The following mutations require the authenticated owner's retained native session (`live_session_id`), current source zone/cell/position, and a stable `request_id`:

- `recruiter_join`: `terminal_id`. A neutral player immediately joins the recruiter's original faction as COVERT (1), presented as Combatant. This deliberately removes the application/200-standing joining gate, without granting standing.
- `recruiter_status_toggle`: `terminal_id`, `expected_status` (0 or 1). A nearby same-faction salute queues the original recruiter callbacks: combatant to on-leave takes 300 seconds, return to combatant takes 30 seconds. Original Jedi and changing-status restrictions remain. The response reports `pending_status` and `delay_ms`; `state.gcw` reports pending/current status and remaining display time.
- `recruiter_promote`: `terminal_id`, `expected_rank`. Uses the original FactionManager next-rank cost, highest-rank boundary, and 200 point reserve, charging standing before applying the original rank. This allows progression beyond the initial native standing cap.
- `recruiter_purchase`: `terminal_id`, opaque `reward_id` (`faction:category:key`). The original `recruiterScreenplay:awardItem` creates the item and charges actual GCW/racial/Bothan/smuggler-adjusted standing. The metadata catalog's base price is never purchase authority. Source standing reserve, inventory/bonus capacity, own faction and active-duty rules apply. Changing status blocks purchases.
- `contraband_answer`: exact native `scan_id`, boolean `accept`. Only an unanswered original phase 9 fine can be answered. No public action starts, forces or advances a scan. The original scheduled task subsequently charges carried/bank credits or applies its faction penalty.

Receipt comparison excludes changing source pose for these mutations but retains semantic IDs/choices/status/rank. Replays return original results and current owned state without repeating charges. Stale expected rank/status and stale scan identities are rejected. Recruiter interaction validates actual source NPC identity, life, same zone/cell and LOS (5 m UI, 3 m salute). Existing services life/combat restrictions remain.

`state.gcw` contains faction, status/name, `pve_only`, current/pending transition, standings, nearby recruiter targeting records, and `scan`. Scan fields include `active`, opaque `id`, native phase/name, scanner ID, remaining original task iterations, fine, pending/answered flags, carried/equipped contraband count, and faction-specific crackdown TEF flags. Original actual scanner spatial speech is replicated by the NPC chatter channel. This Core3 source fines contraband; it does not confiscate it, so no invented confiscation is performed.

Native COVERT status retains faction NPC combat. The current prototype explicitly rejects player-versus-player attackability, including player-owned pets and vehicles, before original duel/TEF/overt checks. No player PvP, bases or advanced GCW operations are enabled. Original faction mission generation, objectives and faction rewards remain in MissionManager; mission rows now include their native faction and faction-point rewards.

Patch 0056 also fixes source scan defects: wild scan managers must select online ready players in their own zone; scan tasks cancel and return when the zone is unavailable; running scans require matching zone/cell and ready living players; contraband recursion includes containers with exactly one child; empty factory prototypes cannot be dereferenced. Original scan probabilities, login delays, 48 hour player cooldown, faction detection and reinforcement tasks remain unchanged. Existing native AI RunCrackdownScan and global wild-scan tasks execute for the retained player sessions.

`runtime/assets/gcw/catalog.json` is extracted from original ordered faction reward Lua/STF and user-owned assets. `SWGXR_GCW_CATALOG_PATH` overrides the native metadata path. Missing metadata disables the reward listing with a server warning; it never invents rewards. Asset provenance and any missing original wearable remain in the ignored catalog.

Validation harness: `python3 tools/server/gcw_smoke.py`. It creates only isolated `invtestgcw*` characters. Administrator setup supplies original recruiter/scanner spawns, credits/standing and spice, while actual joining, promotion, purchases, callbacks, missions and fines use normal native operations. A trusted server-Lua `AiAgent:startContrabandScan(player,enforced)` binding supports authored scans and deterministic fixtures; enforced selection is explicitly not evidence of autonomous random wild-scan selection. No HTTP equivalent exists. Final native results are written to `runtime/evidence/gcw-native.json`; Python input/normalization checks are in `tests/test_gcw_protocol.py`. No VR or remote deployment is part of this test.

Recorded native validation: `runtime/evidence/gcw-native.json` passes 42 checks, including original purchases/promotions and receipts, faction mission acceptance/cancellation, player PvP rejection, NPC combatant/on-leave relations, paid/refused fines, source scanner speech, original 300 second leave and 30 second resume callbacks, reward/standing persistence, and actual Lambda type (AiAgent). The first transaction run completed 35 checks but its combatant fixture died during idle waiting. `gcw_complete_smoke.py` explicitly repaired only that isolated fixture's HAM/posture and verified the original callback and persistence; it did not force faction, rank, standing or duty. The report preserves this history. The default harness now protects only its waiting test character at high source altitude and refreshes both sessions, restoring source ground before interaction checks; this final harness isolation adjustment was syntax-checked, not a second full 300 second run. Seven Python protocol checks pass. Original random autonomous scan selection and reinforcement encounters were not forced into a claimed autonomous-play proof.
